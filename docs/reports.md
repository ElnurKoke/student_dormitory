# Закрытые отчёты реестра, CSV и история

Реализованы `/staff/statistics`, `/staff/registry-export`, `/staff/registry.csv` и `/staff/history`, только GET/HEAD. Ссылки появляются в общей навигации по фактическим правам и назначениям. Все страницы имеют русский/казахский интерфейс, сохраняют язык и параметры фильтров в URL. Предпросмотр экспорта, замечания к карточкам и история имеют пагинацию по 50 строк.

`internal/modules/reports` содержит HTTP-обработчики, сервис отчётов и формирование CSV. SQL остаётся у владельцев данных: `inventory/report_repository.go` и `audit/read_repository.go`. Нет прямого чтения чужих таблиц обработчиками. Auth предоставляет явные `AssignedDormitoriesTx` и `AuthorizeTx`; зависимости собираются в `internal/app`.

## Права и изоляция

| Возможность | Разрешения | Текущая тестовая матрица |
| --- | --- | --- |
| Статистика | `statistics.read` и `registry.read` | Администрация. |
| Предпросмотр и CSV | `registry.export` и `registry.read` | Сотрудник реестра и администрация. |
| История | `audit.read` и `registry.read` | Администрация. |

Каждое разрешение применяется только в назначенных общежитиях. Студент, комендант и системный администратор новых прав не получают. Наличие `registry.read` само по себе не даёт экспорт; назначение без разрешения также недостаточно. Production-матрица и управление правами остаются по Q-07.

Сервис открывает транзакцию, читает актуальные разрешения и назначения через тот же `*sql.Tx`, пересекает разрешённые области и только после этого получает записи. Явно выбранное чужое или отозванное общежитие возвращает 403 независимо от существования записи. Без выбранного общежития и без назначений пользователь с нужными разрешениями получает пустую выборку. Отсутствующее разрешение даёт 403, отсутствие входа — 401.

Inventory выбирает только строки с фактическим общежитием из разрешённого набора, через связи внешних ключей. История фильтрует по сохранённому `audit_events.dormitory_id`. Итого, группировки, замечания, варианты общежитий, количество строк, все страницы и CSV используют только эту область. Подмена `user_id`/роли в URL не задаёт автора: ID пользователя берётся из серверной сессии. Системный администратор не имеет обхода. Следующий запрос учитывает отзыв роли, разрешения, назначения или отключение пользователя.

Все закрытые ответы и файлы имеют `Cache-Control: no-store`. CSV целиком готовится до отправки заголовков; ошибка БД/кодирования не выдаёт частичный успешный файл. Изменения реестра и проверки прав читаются в одном согласованном срезе; отмена и ошибка освобождают транзакцию. В технические логи не добавлены содержимое CSV, история, поисковые значения и ошибки с пользовательскими данными.

## Статистика

Панель показывает число общежитий, комнат, действующих мест; числа мест по `free`, `reserved`, `occupied`, `maintenance`, `unavailable`; распределение всех этих показателей и замечаний по общежитиям. Неопубликованные объекты включены, поскольку это закрытый реестр. Учитываются только неархивные объекты с полностью активной фактической цепочкой родителей. Вместимость не подменяет количество заведённых мест; нулевой фонд показывает нули. Сумма пяти статусов равна количеству действующих мест. Фотографии и история не умножают строки мест.

Числа `reserved`/`occupied` отражают только текущие значения реестра, не количество броней/договоров и не подтверждение фактического проживания. Прогнозы, спрос, очередь, начисления, проценты занятости, процессы бронирования/заселения не добавлены. Партнёрские квоты не предполагаются.

Фильтр `dormitory` выбирает одно разрешённое общежитие. Фильтр замечаний `quality=incomplete` или `quality=no_photos` влияет только на список проблемных карточек; общие числа остаются по выбранному общежитию/всей разрешённой области. `page` управляет страницей замечаний. Панель всегда описывает действующий фонд; `state=archived/all` для неё не поддерживаются.

Неполнота — нарушение существующей проверки обязательных полей карточки общежития или комнаты, например пустое оснащение в старой/импортированной записи. Правила берутся из inventory, новые обязательные характеристики не придумываются. Необязательные описание и пояснение доступности не делают карточку неполной. Отсутствие фотографий считается отдельно для активных общежитий и комнат; фото родителя не заменяют фото комнаты. Карточка с обеими проблемами входит по одному разу в каждый показатель. В списке есть ссылки на реальные карточки и сообщения о незаполненных полях.

`AsOf` — время чтения среза UTC. Следующий запрос после зафиксированной смены статуса, архива или добавления фото отражает новое состояние без кэша.

## CSV

На `/staff/registry-export` работают фильтры:

- `dormitory` — назначенный ID;
- `q` — подстрока ID, названия, адреса, обозначения и родительского пути, без учёта регистра Unicode;
- `state=active|archived|all` — по умолчанию active; архив учитывает собственный флаг и всех родителей;
- `kind=dormitory|building|floor|room|bed` — тип; пустое значение означает все;
- `status=free|reserved|occupied|maintenance|unavailable` — отбирает только места с таким статусом;
- `quality=incomplete|no_photos` — нарушение обязательных полей или отсутствие применимых фото;
- `page` — от 1 до 1000000, по умолчанию 1; остальные фильтры по умолчанию пусты.

Эти же параметры работают на `/staff/registry.csv`. Фильтры применяются одновременно. Кнопка скачивания сохраняет их и язык; файл включает все строки выборки, а не только текущую страницу предпросмотра. Некорректные значения возвращают 400, без частичного CSV. Стабильная сортировка по общежитию, типу и постоянному ID не зависит от количества фото.

Файл содержит одну строку на реальный объект каждого уровня: постоянные ID и родитель, общежитие и путь, название/номер, собственный и эффективный архив, публикацию общежития, его реквизиты, характеристики комнаты, точные целые площадь/стоимость и отдельные валюту/период, статус места, количество фотографий, коды неполных полей, версию и время обновления. Неприменимые значения пустые. Реквизиты оператора доступны только в закрытом экспорте с указанными правами. Пользователи, сессии, основания смены статусов, история, аудит, пути файлов и байты фотографий не экспортируются.

Формат: `text/csv; charset=utf-8`, UTF-8 с BOM, запятая, CRLF и стандартное CSV-экранирование кавычек/разделителей/переносов. Заголовки и коды стабильны и не зависят от языка интерфейса, исходный русский/казахский текст сохраняется. Стоимость — десятичные цифры int64 минимальных денежных единиц, без float и конвертации. При импорте длинных ID/чисел в табличный редактор можно выбрать текстовый тип колонок для сохранения всех цифр.

Каждая ячейка проходит `SpreadsheetCell`: потенциальная формула `=`, `+`, `-`, `@` (также полноширинные варианты), в том числе после пробелов, управляющих символов, BOM или невидимых форматирующих префиксов, получает начальный апостроф. Значения с табуляцией/переносами также принудительно становятся текстом. Это дополняет CSV-кавычки; обычные русские/казахские строки не изменяются. Апостроф является намеренной защитной частью CSV. Защита рассчитана на открытие выгрузки; последующее снятие защитного префикса при обработке не входит в контракт.

## История

Фильтры: `dormitory`, точные `actor`, `action`, `type`, `object`, дни `from`/`to` включительно в UTC, `page`. Текстовые фильтры до 200 символов; дата — `YYYY-MM-DD`, годы 0001–9998. Порядок — время события по убыванию, затем ID, чтобы события с одинаковым временем не терялись между страницами.

Показываются номер события, UTC, автор (постоянный ID), код действия, объект, общежитие, результат, request_id и изменения разрешённых скалярных полей до/после. JSON не становится доверенным HTML: значения экранируются. Числа снимка декодируются через `json.RawMessage`, без потери int64. Неизвестные ключи, вложенные payload и технические пути не выводятся. События без привязки к общежитию, в том числе auth.login/logout и создание пользователей, не входят в журнал реестра. Он сохраняет события архивных объектов в пределах действующих назначений.

Методов записи/редактирования/удаления у читателя аудита нет. Все четыре маршрута отклоняют POST/PUT/PATCH/DELETE с 405. Миграция `000007_registry_export.sql` добавляет отдельное разрешение экспорта, индекс истории и триггеры запрета UPDATE/DELETE `audit_events`, сохраняя INSERT через `RecordChange`. Работники приложения не могут редактировать/удалять аудит. Это не защита от владельца файла БД, способного снять триггеры; сроки хранения, эксплуатационная защита и резервирование остаются по Q-08.

- `internal/app/reports_test.go`: пять ролей и аноним, прямые GET/HEAD и неподдерживаемые методы, подмена общежития, отсутствие чужих маркеров в HTML/CSV, закрытые заголовки, экспорт всех страниц, фильтры, локализация, XSS, отзыв назначения.
- Полный набор прежних тестов проверяет регрессии публичного каталога, прав, CSRF и транзакционного аудита. Новых пользователей и демонстрационного фонда миграция не создаёт.
