# Проверка маршрутов и навигации

Проверено 15.11.2026. Сервер запускается на `http://localhost:8080/` с `APP_ENV=development DEV_LOGIN_ENABLED=true`. HTML и CSS встроены в приложение, после изменений сервер пересобран и перезапущен.

## Причины отсутствия разделов

При обычном запуске `DEV_LOGIN_ENABLED=false`: вход и рабочее меню недоступны. В development-режиме меню формируется после входа по текущим правам. Системный администратор видит учётные записи, но не получает доступ к фонду.

В существующей локальной БД на момент проверки нет общежитий, корпусов, этажей, комнат, мест и фотографий. Назначение `dev-dorm-1` резервирует область доступа, но не создаёт запись фонда. Для начала работы сотрудник реестра должен создать общежитие. Дочерние объекты открываются последовательно из карточек родителей; отдельных общих страниц всех корпусов, этажей или комнат нет.

На главной добавлен переход «Войти для работы с реестром», на странице входа — описание разделов каждой роли. Исправлен переход к ещё не созданному назначенному общежитию: сотрудник реестра получает форму создания, комендант и администрация — список с пояснением вместо 404. Проверка прав и назначения выполняется до перенаправления.

## Карта маршрутов

Все указанные маршруты сверены с регистрацией в `internal/app/app.go`. Включённый development-вход даёт 42 шаблона маршрутов; без него `/auth/login` не регистрируется.

| Группа | Маршрут | Методы | Количество |
| --- | --- | --- | --- |
| Публичные страницы и инфраструктура | `/`, `/healthz`, `/static/app.css` | GET, HEAD | 3 |
| Тестовый вход | `/auth/login` | GET, HEAD, POST | 1 |
| Выход | `/auth/logout` | POST | 1 |
| Кабинет и пользователи | `/account`, `/admin/users` | GET, HEAD | 2 |
| Изображения | `/photos/{photoID}`, `/staff/photos/{photoID}` | GET, HEAD | 2 |
| Реестр | `/staff/dormitories` | GET, HEAD | 1 |
| Создание на каждом из пяти уровней | `{collection}/new` | GET, HEAD, POST | 5 |
| Карточка каждого уровня | `{detail}` | GET, HEAD | 5 |
| Редактирование каждого уровня | `{detail}/edit` | GET, HEAD, POST | 5 |
| Архив каждого уровня | `{detail}/archive` | POST | 5 |
| Восстановление каждого уровня | `{detail}/restore` | POST | 5 |
| Фотографии общежития и комнаты | `{detail}/photos`, `{detail}/photos/{photoID}/edit`, `{detail}/photos/{photoID}/delete` | POST | 6 |
| Статус места | `{bedDetail}/status` | GET, HEAD, POST | 1 |
| Всего | | | 42 |

Коллекции пяти уровней:

```text
/staff/dormitories
/staff/dormitories/{dormitoryID}/buildings
/staff/dormitories/{dormitoryID}/buildings/{buildingID}/floors
/staff/dormitories/{dormitoryID}/buildings/{buildingID}/floors/{floorID}/rooms
/staff/dormitories/{dormitoryID}/buildings/{buildingID}/floors/{floorID}/rooms/{roomID}/beds
```

`{detail}` добавляет к соответствующей коллекции постоянный ID объекта. Списки дочерних объектов находятся на карточке родителя, отдельные GET-маршруты коллекций ниже общежитий не зарегистрированы.

## Результаты

На живом сервере выполнены вход и выход всех пяти существующих тестовых пользователей без вывода паролей, проверены все ссылки основного меню. После исправления доступные ссылки дают 200 либо 303 к форме создания/реестру. Для гостя главная, вход, CSS и healthz отвечают 200; закрытые страницы — 401, отсутствующие страницы/изображения — 404. Проверены GET и HEAD.

`internal/app/routes_test.go` проверяет каждый из 42 зарегистрированных маршрутов на изолированной временной БД: ожидаемый GET/HEAD, общее меню HTML, запрет DELETE с правильным Allow, отказ изменяющим запросам без сессии (401) и без CSRF (403). Отдельный регрессионный тест проверяет переход к ещё не созданному назначенному общежитию для трёх ролей, запрет студенту/системному администратору и запрет чужого назначения. Успешные изменения, фотографии, права, конфликты версий, история, транзакции и ошибки дополнительно проверены существующими тестами inventory, bed, photo, auth, audit и platform.

Успешно выполнены:

```sh
gofmt -w cmd internal migrations web
go test ./...
go vet ./...
go build -o bin/server ./cmd/server
```

В браузере проверены главная, переход на форму входа, обновлённые подсказки ролей и отображение новой ссылки реестра. Предыдущий процесс завершён по SIGTERM с сообщением `server stopped gracefully`; новый процесс обслуживает пересобранное приложение.

Публичный каталог, статистика и общий журнал аудита ещё не реализованы; рабочих маршрутов и навигационных ссылок для них нет. Проверка не меняет статусы этих требований и не подтверждает готовность первого этапа целиком. Деловые данные существующей локальной БД в ходе проверки не создавались и не изменялись; вход/выход создаёт обычные сессионные события аудита.
