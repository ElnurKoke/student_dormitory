# Проверка первого этапа — 15.11.2026

Проверен технический результат по [mvp.md](mvp.md), без признания отложенных процессов, интеграций и организационных условий выполненными. Данные проверки — изолированные временные БД и явно созданный демонстрационный фонд. Рабочий пользовательский фонд не заполнялся и не заменялся. Отчёт не является утверждением production-матрицы, перевода, юридических оснований или эксплуатационной приёмкой владельца продукта.

Также добавлены блокировки совместного использования БД/хранилища сервером и maintenance-командами, чтобы резервная операция не создавала несогласованную пару.

## Демонстрационный набор

```sh
APP_ENV=development DEV_LOGIN_ENABLED=true \
go run ./cmd/demo-data -out var/demo

APP_ENV=development DEV_LOGIN_ENABLED=true HTTP_ADDR=127.0.0.1:8090 \
DATABASE_PATH="$PWD/var/demo/dormitory.db" \
FILES_DIR="$PWD/var/demo/files" \
DEV_USERS_FILE="$PWD/var/demo/dev-users.txt" \
go run ./cmd/server
```

Выходная папка должна отсутствовать. Команда сначала проверяет development-вход, затем создаёт изолированные пути БД, файлов и credentials независимо от окружных DATABASE_PATH/FILES_DIR. Пользователи создаются существующим development-bootstrap после миграций; данные фонда — только явным вызовом демо-сервиса. Сервер, миграции и production не запускают этот сервис. Демо не принимает произвольные роли/user_id, не сбрасывает пароли и не заменяет существующий каталог.

Состав:

- одно опубликованное общежитие `dev-dorm-1`, один корпус, два этажа, три комнаты, шесть заведённых мест;
- действующий фонд: одно общежитие, две комнаты, пять мест — три free, одно maintenance, одно unavailable; reserved/occupied — нули;
- одна полностью архивная ветка: этаж, комната и место; три нормализованных PNG, из которых фото архивной комнаты не публично;
- комната 102 без фотографий, чтобы показать реальное замечание статистики; неполных обязательных полей нет;
- русский/казахский пример содержимого и явно помеченные детерминированные тестовые изображения; это не реальные фотографии или фонд.

`demo.json` содержит постоянные ID созданного набора и ожидаемые количества. Структура/значения/сценарии воспроизводимы, но секреты, сгенерированные ID и timestamps намеренно новые для независимых наборов. Повтор в ту же папку запрещён; повторное заполнение непустого фонда также запрещено. Ошибка после начала наполнения оставляет маркер незавершённости: используйте новую папку, а не снимайте защиту. Тесты — `cmd/demo-data/main_test.go`, `internal/app/acceptance_test.go`.

Пароли пяти тестовых пользователей находятся только в закрытом `var/demo/dev-users.txt`. Используйте логины `dev_student`, `dev_registry_staff`, `dev_commandant`, `dev_administration`, `dev_system_admin`; пароль каждой роли индивидуален. В stdout, отчёт и технические логи пароли не выводятся.

## Воспроизведение проверок

```sh
gofmt -w cmd internal migrations web
go vet ./...
go test ./...
go test -race ./internal/platform/backup ./internal/platform/maintenance
go build -o bin/server ./cmd/server
go build -o bin/demo-data ./cmd/demo-data
go build -o bin/backup ./cmd/backup
```

Процессный тест использует доступный временный localhost-порт и SIGTERM; в ограниченной среде нужно разрешение на локальный TCP. Если системный Go-cache недоступен, задайте отдельный `GOCACHE`, например `/tmp/dormitory-go-cache`. Проверки используют временные пути и не читают рабочие пароли пользователя.

Для повторной визуальной проверки можно экспортировать те же HTML и разрешённые тестовые изображения:

```sh
DORM_VISUAL_OUT=/tmp/dormitory-mvp-visual \
go test ./internal/app -run '^TestMVPFullLifecycleAndRecovery$' -count=1
python3 -m http.server 8093 --bind 127.0.0.1 \
  --directory /tmp/dormitory-mvp-visual
```

Папка также должна быть новой. Файлы `catalog-ru.html`, `catalog-detail-kk.html`, `inventory-kk.html`, `statistics-kk.html`, `history-ru.html`, `export-kk.html` и противоположные языковые варианты доступны по localhost:8093. Это статические снимки для вёрстки; формы/навигация в них не являются действующим приложением. CSRF-токены заменены тестовым маркером; credentials/SQLite в эту папку не записываются. После проверки остановите временный HTTP-сервер.

## Что остаётся

Партнёрские квоты, полный цикл заявлений/очереди/брони/заселения/переселения, электронные основания, все отложенные интеграции и прогнозы не реализованы. Production-вход, утверждённая матрица и реальные назначения, общий журнал вне фонда, политика хранения/защиты аудита, редакционное утверждение казахского перевода и расширенная проверка устройств остаются. Не назначены владельцы данных, ответственность за публикацию, эксплуатационные показатели, обучение и поддержка. Offline-копии реализованы и восстановлены, но расписание, шифрование/offsite, ротация, RPO/RTO и эксплуатационный масштаб не подтверждены. Это сохраняет частичный статус составных пунктов в [requirements.md](requirements.md).
